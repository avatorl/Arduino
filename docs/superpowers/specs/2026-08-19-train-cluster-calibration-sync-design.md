# Train Cluster Calibration Synchronization Design

## Goal

Keep `arduino-train-v2` synchronized with the cluster-based data generated by
`rgb-color-sensor/calibration_tool.py` without manual translation of cluster
centers, radii, thresholds, or label ordering.

This change does not capture new calibration data or change the clustering
algorithm.

## Scope

- Add a train-target form of the existing `analyze-clusters` output.
- Replace the train sketch's manually adapted generated region with the
  train-target output from the current checked-in dataset.
- Keep the train's current white balancing, normalization, nearest-valid-cluster
  matching, marker transition handling, and marker actions.
- Document how to regenerate the train block after captures are changed.

## Generated Train Block

The Python tool will accept an explicit target option for the cluster analysis
command. Its train target will emit valid Arduino/C++ declarations for:

- `colorClearMinThreshold`
- `colorMatchClearThreshold`
- `whiteBalanceRedGain`, `whiteBalanceGreenGain`, and `whiteBalanceBlueGain`
- `MarkerClusterDefinition markerClusters[]`
- `markerClusterCount`

Each generated cluster entry will use the train's `TrackMarkerClass` enum
constant rather than the generic recognition sketch's numeric label index.
The formatter will derive those enum constants from a fixed, explicit mapping
of supported capture labels:

| Capture label | Train marker enum |
| --- | --- |
| White | `MarkerWhite` |
| Brown | `MarkerBrown` |
| Cyan | `MarkerCyan` |
| Green | `MarkerGreen` |
| Grey | `MarkerGrey` |
| Magenta | `MarkerMagenta` |
| Orange | `MarkerOrange` |
| Red | `MarkerRed` |
| Yellow | `MarkerYellow` |

The formatter must fail with a clear error when a capture label has no train
marker mapping. It must not omit an unsupported color or substitute
`MarkerUnknown`.

The existing generic `analyze-clusters` output remains unchanged for the
standalone recognition sketch.

## Train Integration

The train sketch will retain the existing generated-data delimiters and source
artifact comment, updated to identify the train-target command. The generated
region will be copied verbatim from the train-target output.

`classifyTrackMarkerColor` will continue to:

1. reject readings below the generated clear thresholds;
2. apply the generated white-balance gains;
3. normalize the balanced RGB values;
4. select the nearest generated marker cluster only when the measured distance
   is within that cluster's generated radius; and
5. return `MarkerUnknown` when no cluster matches.

The marker-action switch remains outside generated data so train behavior is
not determined by calibration labels alone.

## Error Handling

- Missing required calibration labels continue to fail through the existing
  validation path.
- A label unsupported by the train target fails before any output is written.
- The train sketch continues to classify low-light or unmatched samples as
  unknown, so no marker action runs.

## Validation

- Confirm the train-target output contains the same current thresholds, gains,
  19 centers, and 19 radii as the checked-in dataset.
- Confirm every emitted enum maps to an existing `TrackMarkerClass` value.
- Compile `arduino-train-v2` for its Nano/ATmega328P target.
- Confirm the generic cluster output and standalone recognition sketch are
  unchanged.

## Non-Goals

- Recalibrating or recapturing sensor data.
- Changing cluster selection, white-balance calculation, or threshold
  derivation.
- Defining new train actions for marker colors.
- Replacing the enum-based marker action model with runtime string matching.
